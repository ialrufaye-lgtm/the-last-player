# نشر لعبة THE LAST PLAYER على الإنترنت 🚀

اللعبة مكوّنة من قطعة واحدة تُنشر معًا (Docker): السيرفر + واجهة اللعب.
أي منصة تدعم Docker تنفع. أسرع خيارين مجانيين:

## الخيار 1: Render (الأسهل — بدون أوامر)

1. أنشئ حسابًا مجانيًا على https://render.com واربط حساب GitHub.
2. ارفع مجلد `last-player` إلى مستودع GitHub خاص بك.
3. في Render: **New → Web Service** → اختر المستودع.
4. الإعدادات:
   - **Environment:** `Docker`
   - **Dockerfile Path:** `./Dockerfile`
   - الخطة المجانية (Free) تكفي للتجربة.
5. اضغط **Deploy** — بعد دقائق ستحصل على رابط مثل:
   `https://the-last-player.onrender.com`
6. شارك الرابط مع اللاعبين — يدخلون من المتصفح مباشرة، بلا تثبيت.

> ملاحظة: الخطة المجانية في Render تُسبِت الخدمة بعد 15 دقيقة من الخمول،
> فأول لاعب يدخل قد ينتظر ~30 ثانية حتى تستيقظ. للعب الجاد استخدم خطة مدفوعة
> (تبدأ من ~7$/شهر) أو الخيار 2.

## الخيار 2: Fly.io (يبقى مستيقظًا)

1. ثبّت `flyctl` وأنشئ حسابًا: https://fly.io/docs/hands-on/install-flyctl/
2. من داخل مجلد `last-player`:
   ```bash
   fly launch --no-deploy
   # اختر اسمًا للتطبيق وregion قريبًا من لاعبيك
   fly deploy
   ```
3. ستحصل على رابط مثل: `https://the-last-player.fly.dev`

## إعدادات مهمة

| متغير | معناه | الافتراضي |
|---|---|---|
| `PORT` | منفذ السيرفر (تضبطه المنصة تلقائيًا غالبًا) | `2567` |
| `MIN_PLAYERS` | أقل عدد لاعبين لبدء مباراة | `10` |
| `VITE_SERVER_URL` | عنوان السيرفر للواجهة — **لا حاجة لضبطه**؛ نسخة الإنتاج تستخدم نفس الرابط تلقائيًا (`wss://`) | — |

المضيف (أول من ينشئ الغرفة) يضغط «ابدأ» عندما يكتمل العدد.
رمز الغرفة المكوّن من 4 أحرف يظهر في اللوبي لمشاركته مع الأصدقاء.

## اختبار محلي قبل النشر

```bash
# 1) السيرفر
cd server && npm install && npm run build && DEV_MIN_PLAYERS=4 npm start

# 2) محاكاة 100 لاعب وهمي (في نافذة أخرى)
cd tools && npm install && npx tsx bot.ts --n=100 --target=100
# راقب: جولات كاملة → منصة تتويج بفائز واحد 🏆

# 3) واجهة اللعب للتطوير
cd client && npm install && npm run dev  # http://localhost:5173
```
